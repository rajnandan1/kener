Release date: **November 19, 2026**

> [!IMPORTANT]
> Upgrade if you use hidden monitors. Before v4.2.2, an incident or maintenance that affected only hidden monitors was public on the events page, in `/rss.xml`, and on its own incident or maintenance page. See [Events of hidden monitors](#hidden-only-events).

## Events of hidden monitors {#hidden-only-events}

A hidden monitor has `is_hidden = YES`. A global event (`is_global = YES`) shows on every status page, whatever monitors it affects. New incidents and maintenances are global by default.

Before v4.2.2, Kener removed hidden monitors from the affected monitors that an event page shows. The event itself stayed public. So a non-global incident or maintenance that affected only hidden monitors showed its title, description, and comments in these places:

- The events page at `/events/{month}-{year}`.
- The RSS feed at `/rss.xml`.
- The incident page `/incidents/{id}` and the maintenance page `/maintenances/{id}`.

Kener now shows an event in these places only when the event is global or affects a monitor that is not hidden. When an event is not global and affects only hidden monitors, its incident or maintenance page returns 404. A signed-in user whose role has `monitors.read` sees hidden monitors, so that user can still open the page of an event that affects only hidden monitors. See [Monitor Visibility](/docs/v4/monitors/visibility#where-each-rule-applies).

The same rule applies to a non-global event that has no affected monitors, for example because you deleted its monitors. It also stays off these lists and pages.

What to do:

1. Upgrade to v4.2.2.
