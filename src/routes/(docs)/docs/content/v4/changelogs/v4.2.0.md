Release date: **November 4, 2026**

> [!IMPORTANT]
> Custom `eval` code now runs in a sandbox. Eval code that uses Node.js features such as `fetch`, `process`, or `Buffer` stops working and reports **DOWN**. Check your custom evals before you upgrade. See [What to do](#what-to-do).

## Custom eval sandbox {#eval-sandbox}

API, Ping, TCP, and GameDig monitors now run custom `eval` code in a [sandbox](/docs/v4/monitors/overview#eval-sandbox). The sandbox keeps the JavaScript language, `modules.cheerio`, `atob`, and `btoa`. `console` still works but writes nothing.

- Each eval has a limit of 10 seconds and 256 MB. An eval that goes over a limit reports **DOWN** with type `ERROR`.
- All four monitor types now accept only `UP`, `DEGRADED`, `DOWN`, or `MAINTENANCE` as a `status`. Before, Ping, TCP, and GameDig saved any other value as it was. Now such a value reports **DOWN** with type `ERROR`.
- A GameDig eval with a syntax error now reports **DOWN**. Before, the check failed with no result.
- An invalid `status` error now names the value that the eval returned.
- Cheerio runs about 20 times slower in the sandbox. A 1 MB page takes about 2 seconds.
- `modules.cheerio` keeps `load`, `contains`, and `merge`. It no longer has `fromURL`, `loadBuffer`, `stringStream`, or `decodeStream`. Kener loads it only when the eval contains the word `cheerio`.
- `Intl` does not exist in the sandbox, so `toLocaleString()` no longer adds thousands separators or local date formats.
- A response body above 100 MB can go over the memory limit and report **DOWN**.

## What to do {#what-to-do}

1. Search your custom evals for `fetch`, `process`, `require`, `import(`, `Buffer`, `setTimeout`, `URL`, `TextDecoder`, `crypto`, and `Intl`.
2. Rewrite each eval that uses one of these. To replace `fetch`, see [Replace `fetch` in an eval](/docs/v4/monitors/overview#replace-fetch).
3. After you upgrade, look for `is not defined` in the error of each monitor that reports **DOWN**.
