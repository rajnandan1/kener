Release date: **October 27, 2026**

> [!IMPORTANT]
> This release fixes a security issue in v4.0.0 to v4.1.10. Upgrade, then check whether you need to rotate the secrets stored in your monitors. See [Security](#security).

## Security {#security}

### The REST API returned monitor secrets to any API key {#monitor-secrets}

| Field             | Value                                                                       |
| ----------------- | --------------------------------------------------------------------------- |
| Affected versions | v4.0.0 to v4.1.10                                                           |
| Fixed in          | v4.1.11                                                                     |
| Severity          | Medium, CVSS 3.1 score 6.5 (`CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N`) |
| Weakness          | CWE-522 (Insufficiently Protected Credentials)                              |

`GET /api/v4/monitors`, `GET /api/v4/monitors/{tag}`, and the response of `PATCH /api/v4/monitors/{tag}` returned the full `type_data` of each monitor in plain text. Any valid API key could read these values:

- Each `headers` value of an API or Prometheus monitor, such as `Authorization: Bearer ...`.
- The request `body` of an API monitor.
- The `proxy` URL, with its user name and password.
- The `connectionString` of a SQL monitor.
- The `secretString` of a heartbeat monitor. A user who knows it can send fake heartbeats.
- The `tlsKey` of a Docker monitor.

Kener now shows each of these values as `********` in every API response except the `POST /api/v4/monitors` response. Monitor checks still use the real values.

What to do:

1. Upgrade to v4.1.11.
2. If anyone outside your administrators held an API key, treat the values above as exposed. Rotate each one where it was issued: the API token, the database password, the proxy password, or the Docker TLS key.
3. For each heartbeat monitor, set a new **Heartbeat secret** in the monitor settings, or click **New URL**. Then give the new URL to the sender.

A value written as a `$SECRET` reference, such as `Bearer $API_TOKEN`, stays in an environment variable. The API returned only the reference, so that secret was not exposed.

> [!NOTE]
> A `PATCH /api/v4/monitors/{tag}` that sends a masked value back keeps the stored secret. To change a secret, send the new value.
