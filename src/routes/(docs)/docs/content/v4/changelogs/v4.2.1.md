Release date: **November 9, 2026**

> [!IMPORTANT]
> Upgrade if you run v4.2.0 with API, Ping, TCP, or GameDig monitors. In v4.2.0 the eval sandbox can hang, and then each of these monitors reports **DOWN** until Kener restarts. See [Eval sandbox hang](#eval-hang).

## Eval sandbox hang {#eval-hang}

In v4.2.0, Kener ran each eval in a new Node.js worker thread. Under load, Node.js could deadlock the background thread pool that all worker threads share ([nodejs/node#54918](https://github.com/nodejs/node/issues/54918)). After that:

- Every eval failed with `Eval error: Timed out after 10000 ms`.
- Every API, Ping, TCP, and GameDig monitor reported **DOWN**, while its target worked.
- Kener used more memory each minute, until it was restarted or ran out of memory.

See [issue #928](https://github.com/rajnandan1/kener/issues/928).

Kener now runs each eval in its own short-lived process:

- At most 2 evals run at once. The next eval waits for a free slot, and its 10 seconds start when it begins to run. See [Custom eval sandbox](/docs/v4/monitors/overview#eval-sandbox).
- Eval code keeps the same language, limits, and error messages as in v4.2.0.
- `Date` in eval code still uses the time zone of the server.

What to do:

1. Upgrade to v4.2.1.
2. If you start Node.js with `--no-wasm-tier-up` as a workaround, remove the flag. Kener no longer needs it.
